# CSV Mapping and Power BI Online Import Guide

This guide explains how to fill the CSV files generated by `--assess` or `--export`, then apply the mappings to Power BI Online.

## 1. Generate the files

Run a read-only assessment first:

```powershell
python migrate.py --server https://pbirs.company.com/reports --assess --use-windows-auth --output-dir artifacts/assessment
```

The mapping files are written to `artifacts/assessment/`:

- `folders_mapping.csv`
- `users_mapping.csv`
- `folder_access_mapping.csv`
- `connections_mapping.csv`

The assessment also writes `permissions.json`, `security.json`, and `rls_ols_role_accounts.csv` for review.

Assessment enriches the PBIRS catalog sequentially in batches of 15 by default. This limits request bursts against the source server. Override with `--catalog-batch-size N` if the server requires a smaller or larger batch.

## 2. Fill the CSV files

Use a CSV-aware editor such as Excel, Power Query, or a text editor that preserves UTF-8 and CSV quoting. Do not rename columns or change the source columns.

### `folders_mapping.csv`

This file controls workspace creation and folder-to-workspace routing.

| Column | Fill? | Meaning |
|--------|-------|---------|
| `folder_path` | No | Original PBIRS folder path |
| `item_count` | No | Number of source items |
| `content_types` | No | Source content types |
| `target_workspace` | **Yes** | Target Power BI workspace name |
| `notes` | Optional | Migration notes |

Example:

```csv
folder_path,item_count,content_types,target_workspace,notes
/Finance,12,PowerBIReport;Report,Finance Reports,Shared finance workspace
/HR,6,PowerBIReport,HR Reports,Restricted access
```

Rules are matched by the longest folder prefix. Map parent folders carefully: a child folder can override its parent with a more specific mapping.

### `users_mapping.csv`

This file maps source PBIRS principals to Microsoft Entra ID users or groups.

| Column | Fill? | Meaning |
|--------|-------|---------|
| `pbirs_principal` | No | Original AD user/group |
| `type` | No | Detected principal type |
| `domain` | No | Source domain |
| `ssrs_roles` | No | Detected SSRS roles |
| `item_count` | No | Source access count |
| `target_azure_ad` | **Yes** | Entra UPN, group email, or object identity accepted by Power BI |
| `target_pbi_role` | Review/edit | Suggested workspace role |
| `notes` | Optional | Identity or security notes |

Do not put passwords or secrets in this file. For groups, use the Azure AD/Microsoft Entra group identity that can be added to the Power BI workspace.

### `folder_access_mapping.csv`

This file scopes permissions to each source folder. It prevents a user who only has Finance access from being added to the HR workspace.

| Column | Fill? | Meaning |
|--------|-------|---------|
| `folder_path` | No | Source PBIRS folder |
| `pbirs_principal` | No | Source user/group |
| `type` / `domain` | No | Detected principal metadata |
| `ssrs_roles` | No | Source roles |
| `item_count` | No | Effective access count |
| `target_workspace` | Usually no | Filled from `folders_mapping.csv`; can override per row |
| `target_azure_ad` | Optional | Override identity from `users_mapping.csv` |
| `target_pbi_role` | Review/edit | Final Power BI workspace role for this folder scope |
| `notes` | Optional | Review notes |

Normally, fill `target_pbi_role` only when the suggested role needs adjustment. Keep the source folder and principal values unchanged.

### `connections_mapping.csv`

This file maps PBIRS connections to Power BI gateway datasources.

| Column | Fill? | Meaning |
|--------|-------|---------|
| `report_name` / `report_path` | No | Source report |
| `datasource_type` | No | Source connection type |
| `connection_string` | No | Original connection string |
| `needs_gateway` | No | Whether an on-premises gateway is expected |
| `target_workspace` | **Yes** | Target workspace name |
| `target_gateway_name` | **Yes** for on-premises data | Exact Power BI gateway display name |
| `target_datasource_name` | **Yes** for on-premises data | Exact datasource name under the gateway |
| `target_gateway_id` / `target_datasource_id` | Legacy optional | IDs are resolved automatically when names are supplied |
| `notes` | Optional | Connection notes |

Use names rather than IDs. The importer lists gateways and datasources in Power BI Online, matches names case-insensitively, and then uses the returned IDs for the bind operation.

For paginated reports, PBIRS may return an empty `/Reports(...)/DataSources` response. The assessment then reads the RDL XML, extracts `ConnectionProperties/ConnectString`, and resolves `DataSourceReference` against the shared PBIRS datasource catalog. The server and database are kept inside the connection string for the importer but are not exposed as separate CSV columns.

Connection strings containing commas are valid. The generator writes them with CSV quoting automatically, for example:

```csv
"Data Source=sql01;Initial Catalog=Finance,Archive"
```

Do not split this value into multiple columns. Always load the file through a CSV parser.

## 3. Apply the mappings to Power BI Online

The CSV orchestration script creates the folder map, resolves gateway mappings, imports converted content, applies workspace permissions, and validates each workspace:

```powershell
python scripts/csv_to_pbi_online_import.py `
    --converted-dir artifacts/converted `
    --csv-dir artifacts/assessment `
    --run-dir artifacts/csv_import_run `
    --tenant-id <TENANT_ID> `
    --client-id <CLIENT_ID> `
    --client-secret <CLIENT_SECRET> `
    --create-missing-connections `
    --verbose
```

For an already acquired Power BI token, use:

```powershell
python scripts/csv_to_pbi_online_import.py `
    --converted-dir artifacts/converted `
    --csv-dir artifacts/assessment `
    --run-dir artifacts/csv_import_run `
    --pbi-token "$env:PBI_ACCESS_TOKEN" `
    --verbose
```

The script performs these operations in order:

1. Reads `folders_mapping.csv` and creates `map_folder.json`.
2. Reads `connections_mapping.csv` and creates `gateway_mapping.generated.json`.
3. Resolves gateway and datasource names to current Power BI IDs.
4. Runs `migrate.py --import` with `--map-folder` and the generated gateway map.
5. Applies workspace users from `folder_access_mapping.csv` joined to `users_mapping.csv`.
6. Validates each mapped workspace and writes `csv_import_summary.json`.

Use `--dry-run` first:

```powershell
python scripts/csv_to_pbi_online_import.py `
    --converted-dir artifacts/converted `
    --csv-dir artifacts/assessment `
    --run-dir artifacts/csv_import_dry_run `
    --pbi-token "$env:PBI_ACCESS_TOKEN" `
    --dry-run `
    --verbose
```

## 4. Verify the result in Power BI Online

Check the generated files:

- `map_folder.json`: folder-to-workspace rules used by the import.
- `gateway_mapping.generated.json`: resolved gateway/datasource IDs used for binding.
- `csv_import_summary.json`: workspace count, gateway summary, permission summary, and validation status.
- `validation/<workspace>/`: validation reports for each target workspace.

In Power BI Service, verify:

1. Every expected target workspace exists.
2. Reports are in the workspace selected by their source folder mapping.
3. Workspace users/groups match `folder_access_mapping.csv` after identity substitution.
4. Gateway bindings point to the datasource names entered in `connections_mapping.csv`.
5. Refresh and report access work for a test user from each security group.

Power BI workspace permissions are workspace-level. If two source folders have incompatible access patterns, map them to separate target workspaces or use Power BI Apps/RLS for the remaining granularity.

## Common errors

- **`No usable rows in folders_mapping.csv`**: fill `target_workspace` for at least one folder.
- **Workspace user not found**: check `target_azure_ad` in `users_mapping.csv`.
- **Gateway not found**: check the exact gateway display name in Power BI Service.
- **Datasource not found**: check the exact datasource name under the selected gateway.
- **Connection string appears split**: reopen the file with a CSV-aware tool; values containing commas must remain quoted.
- **User appears in the wrong workspace**: check `folder_access_mapping.csv` and the longest matching folder rule in `folders_mapping.csv`.
